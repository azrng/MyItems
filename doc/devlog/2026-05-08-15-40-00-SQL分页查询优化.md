# SQL 分页查询优化

## 本次目标
- 将首页和物品库列表从全量 DTO 缓存后内存分页，改为 SQLite 条件分页查询。
- 保留全局物品缓存给临期页、标题栏提醒等仍需全量快照的低频入口。
- 降低大数据量下物品库首屏加载、分类切换、搜索和滚动加载的内存压力。

## 核心改动
- 新增 `ItemQueryOptions` 与 `PagedItemDisplayResult`，为数据服务提供分页查询契约。
- `SqliteDataService.GetItemDisplayPageAsync` 使用参数化 `WHERE`、`COUNT(*)`、`ORDER BY`、`LIMIT` 和 `OFFSET` 查询指定页。
- SQL 分页支持分类、列表搜索、高级搜索关键词、价格、购买日期、保质期日期、有保质期、临期和已过期条件。
- 首页和物品库列表改为首屏查第一页、滚动查下一页，不再维护全量 `_sourceItems` / `_allItems` 做内存分页。
- 物品库顶部统计改为 `GetStatisticsAsync` 的 SQL 聚合查询，避免为统计拉取全量 DTO。
- 删除物品后失效缓存并刷新当前分页列表，保证统计与列表重新从数据库读取。
- 补充首页和物品库分页加载、分类筛选、搜索筛选、滚动加载的单元测试。
