# 编辑页原生控件同步诊断

## 本次目标

- 根据 Android 日志确认 ViewModel 已拿到编辑草稿后，继续定位为什么界面控件仍显示默认值。

## 核心改动

- 编辑页改为 `PushModalAsync` 打开，避开普通导航栈可能残留的 Shell 顶栏占位。
- 为编辑页关键原生控件增加 `x:Name`，在 `Loaded` 和 `OnAppearing` 后从 ViewModel 快照显式同步控件值。
- 新增 `[AddItemPage] Sync controls ...` 诊断日志，用于确认原生控件层是否已收到 `ItemName`、分类和数量。
- 保存与返回改为优先关闭 modal 栈，兼容 modal 与普通页面两种打开方式。

## 修改文件

- `src/MyItems/ViewModels/AddItemViewModel.cs`
- `src/MyItems/ViewModels/ItemDetailViewModel.cs`
- `src/MyItems/Views/AddItemPage.xaml`
- `src/MyItems/Views/AddItemPage.xaml.cs`

## 校验情况

- 已执行：`dotnet build src\MyItems\MyItems.csproj -f net10.0-windows10.0.19041.0 --no-restore`，Windows 目标构建通过。

## 风险或遗留项

- 仍需 Android 端查看 `[AddItemPage] Sync controls ...` 日志和界面截图，确认问题位于控件同步前还是同步后。
- 构建仍输出既有 `MVVMTK0045` 警告，本次未处理其它 ViewModel。
