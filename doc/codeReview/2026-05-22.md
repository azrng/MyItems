## P0 — 必须修复（7 项）

### P0-1. `repository.dart` 是 God Class

**文件**：`lib/repository.dart`（978 行）
**问题**：`ItemRepository` 同时承担数据库 schema 创建/迁移、全部 CRUD、备份导出/导入、CSV 解析/生成、数据种子。违反单一职责原则，任何一个维度的变更都影响其他维度。

**建议拆分**：
- `schema.dart` — 表结构定义与迁移
- `sqlite_repository.dart` — 纯 CRUD 查询
- `backup_service.dart` — 备份导出/导入/解析
- `csv_service.dart` — CSV 导出/导入

### P0-2. `pages.dart` 是 2267 行单文件

**文件**：`lib/pages.dart`
**问题**：包含 20+ Widget 类（RootPage、HomePage、ExpiringPage、LibraryPage、ItemDetailPage、AddItemPage、CategoryPage、StoragePage、AboutPage、LocationPage、ArchivedItemsPage、ConsumptionRecordsPage 及若干辅助组件）。Flutter 项目惯例是一个 Widget 一个文件。

**建议拆分**：
```
lib/

    ...
```

### P0-3. `onOpen` 每次打开数据库都跑全套 schema 操作

**文件**：`lib/repository.dart:35-39`
**问题**：
```dart
onOpen: (db) async {
  await _createSchema(db);      // 6 次 CREATE TABLE IF NOT EXISTS
  await _migrateSchema(db);     // 2 次 ALTER TABLE 检查 + 2 次 UPDATE
  await _seedPresetCategories(db); // 5 次 INSERT
  await _seedPresetLocations(db);  // 4 次 INSERT
},
```
每次 app 启动都执行 17+ 次不必要的数据库操作。`_createSchema` 用的是 `IF NOT EXISTS`，所以不会报错但浪费 I/O。`_migrateSchema` 中的 UPDATE 更是每次全表扫描。

**建议**：
- `onCreate` 做初始化
- `onUpgrade` 做版本迁移
- `onOpen` 不应有副作用
- `_seedPresetCategories` 用 `INSERT OR IGNORE` 且只在 `onCreate` 和版本升级时执行

### P0-4. `getStatistics()` 加载 10,000 条记录做内存聚合

**文件**：`lib/repository.dart:525-543`
**问题**：
```dart
final displays = await getItemDisplays(query: const ItemQuery(limit: 10000));
```
加载最多一万条完整记录到 Dart，再用 `fold` 计算 `totalSpent` 和 `validItems`。数据量增长后会成为性能瓶颈。

**建议改为 SQL 聚合**：
```sql
SELECT
  COUNT(*) as total_items,
  SUM(CASE WHEN expiry_date IS NULL OR expiry_date > date('now', '+7 days')
      THEN 1 ELSE 0 END) as valid_items,
  SUM(CASE WHEN expiry_date IS NULL OR expiry_date > date('now', '+7 days')
      THEN purchase_price * remaining_quantity ELSE 0 END) as total_spent
FROM items WHERE is_archived = 0
```

### P0-5. 测试替身继承具体类而非抽象接口

**文件**：`test/app_store_test.dart:197-368`
**问题**：`FakeHomeRepository` 和 `FakeCategoryRepository` 直接继承 `ItemRepository`，被迫 override 所有方法。当 `ItemRepository` 新增方法时，编译器不会提示测试需要补实现。

**建议**：提取 `abstract class ItemRepositoryBase`（或 Dart 3 的 `interface class`），让 `ItemRepository` 和所有 Fake 类都实现该接口。

### P0-6. `result.success()` 在后台线程调用（Android 原生）

**文件**：`android/.../MainActivity.kt:56-65`
**问题**：
```kotlin
Thread {
    val path = writeBackup(fileName, content)
    result.success(path)  // ← 后台线程调用 MethodChannel result
}.start()
```
Flutter MethodChannel 的 `result` 回调必须在平台主线程调用。在后台线程调用可能导致 `IllegalStateException` 或结果丢失。

**建议**：
```kotlin
Thread {
    try {
        val path = writeBackup(fileName, content)
        Handler(Looper.getMainLooper()).post {
            result.success(path)
        }
    } catch (error: Exception) {
        Handler(Looper.getMainLooper()).post {
            result.error("SAVE_BACKUP_FAILED", error.message, null)
        }
    }
}.start()
```

### P0-7. `ensureWriteStoragePermission()` 阻塞主线程

**文件**：`android/.../MainActivity.kt:86`
**问题**：
```kotlin
return future.get()  // 无限阻塞主线程
```
如果权限弹窗因任何原因未触发（如 Activity 已销毁），`future.get()` 永不返回，直接触发 ANR。

**建议**：改为回调式或使用 `ActivityResultContracts.RequestPermission()`。

## P1 — 应该修复（9 项）

### P1-1. `consumeAll` 中 `getItem` 在 `_run` 错误处理之外

**文件**：`lib/app_store.dart:169-173`
```dart
Future<void> consumeAll(String itemId) async {
  final item = await repository.getItem(itemId);  // ← 不在 _run 中
  if (item == null) { throw ... }
  await _run(() async { ... });
}
```
如果 `getItem` 抛出非 `StoreException`/`RepositoryException` 的异常，不会被 `_run` 的 catch 处理，`errorMessage` 不会被设置，UI 不会显示错误状态。

**建议**：将 `getItem` 也放入 `_run` 包裹内。

### P1-2. `build()` 方法中有副作用

**文件**：`lib/pages.dart:869`
```dart
_form.categoryId ??= store.categories.isEmpty ? null : store.categories.first.id;
```
在 `AnimatedBuilder.builder` 中修改 form 状态，违反 Flutter 单向数据流。`builder` 可被框架多次调用，每次都会触发 `??=` 的判断。

**建议**：在 `initState` 或 `didChangeDependencies` 中初始化 `_form.categoryId`。

### P1-3. `DropdownButtonFormField` 使用不存在的 `initialValue` 参数

**文件**：`lib/pages.dart:883, 908`
**问题**：Flutter 的 `DropdownButtonFormField` 没有 `initialValue` 参数，正确的是 `value`。编译通过是因为 `initialValue` 被当作 `FormField` 基类的参数，但下拉框不会显示初始选中值。

**建议**：将 `initialValue` 改为 `value`。

### P1-4. `newId()` 基于时间戳，批量操作有碰撞风险

**文件**：`lib/models.dart:507`
```dart
String newId() => DateTime.now().microsecondsSinceEpoch.toString();
```
批量导入 CSV/备份时连续调用 `newId()` 可能得到相同的微秒值，导致 ID 碰撞，数据被 `ConflictAlgorithm.replace` 覆盖。

**建议**：使用 UUID v4 或 `microsecondsSinceEpoch.toString() + Random().nextInt(100000).toString()`。

### P1-5. `_migrateSchema` 中 UPDATE 无条件执行

**文件**：`lib/repository.dart:156-165`
```sql
UPDATE items SET initial_quantity = quantity
WHERE initial_quantity IS NULL OR initial_quantity < 1
```
每次打开数据库都执行这条全表扫描 UPDATE。应在迁移版本记录表中检查是否已执行过。

### P1-6. `getItemDisplays` 内存中过滤应下推到 SQL

**文件**：`lib/repository.dart:456-463`
`hasExpiry`、`onlyExpired`、`onlyExpiring` 的过滤在 Dart 侧完成，意味着需要从 DB 加载更多数据再丢弃。应在 SQL WHERE 子句中直接过滤。

### P1-7. `clearAllData` 没有使用事务

**文件**：`lib/repository.dart:745-753`
```dart
await db.delete('items');
await db.delete('consumption_records');
// 如果这里失败，数据不一致
await db.delete('locations', where: 'is_active = 0');
await db.delete('categories', where: 'is_preset = 0');
```
应包裹在 `db.transaction(...)` 中。

### P1-8. 搜索无防抖

**文件**：`lib/pages.dart:1933`
`SearchField.onChanged` 每次按键直接调用 `store.setHomeSearch`，触发完整的数据库查询 + UI 刷新。

**建议**：添加 300ms debounce，可使用 `Timer` 实现：
```dart
Timer? _debounce;
void _onChanged(String value) {
  _debounce?.cancel();
  _debounce = Timer(const Duration(milliseconds: 300), () {
    widget.onChanged(value);
  });
}
```

### P1-9. `ItemDetailPage` 的 FutureBuilder 每次 rebuild 创建新 Future

**文件**：`lib/pages.dart:681`
```dart
FutureBuilder<Item?>(
  future: store.getItem(itemId),  // 每次 build 新建
```
`FutureBuilder` 在 future 实例变化时会重新订阅，导致重复查询。

**建议**：将 future 缓存在 State 中，在 `initState` 创建一次。

## P2 — 建议改进（8 项）

### P2-1. `categoryById` 线性查找可优化

**文件**：`lib/app_store.dart:101-107`
维护一个 `Map<String, Category>` 做O(1)查找。

### P2-2. `_sortByCreatedDesc` 每次创建新列表副本

**文件**：`lib/app_store.dart:354`
`[...items]` 复制后排序。SQL 已经 `ORDER BY created_at DESC`，Dart 侧再排序是冗余操作。

### P2-3. `copyWith` 无法区分"设为 null"和"保持不变"

**文件**：`lib/models.dart:212-253`
`icon: icon ?? this.icon` — 传 null = 保持不变，无法显式清除 `icon`、`brand`、`notes` 等可选字段。可参考 `freezed` 包的 `copyWith` 实现或使用 sentinel 值。

### P2-4. CategoryPage 中 preset 和 custom 分类 ListTile 大量重复

**文件**：`lib/pages.dart:1096-1180`
`leading`、`title`、`trailing` 结构几乎一样，只差 `Dismissible` 包裹和 `lock` 图标。应抽出 `_CategoryTile` 组件。

### P2-5. 测试覆盖薄弱

- 5 个测试文件中只有 `app_store_test.dart` 有 7 个有效测试
- `backup_format_test.dart`、`repository_csv_test.dart`、`status_helper_test.dart`、`navigation_test.dart` 各仅 4-5 个符号
- 关键数据路径（备份恢复、CSV 导入导出、数据迁移）无测试
- 无 widget 测试

### P2-6. 备份文件无完整性校验

`exportBackup` 生成明文 JSON，无签名或 HMAC。恶意修改备份文件后导入可能导致数据损坏或应用崩溃。建议至少加 checksum 校验。

### P2-7. `openUrl` 不校验 URL scheme

**文件**：`android/.../MainActivity.kt:35-45`
`Uri.parse(url)` 不限制 scheme，`file://`、`content://`、`javascript:` 都可能被传入。应只允许 `http://` 和 `https://`。

### P2-8. `permissionFuture` 非线程安全

**文件**：`android/.../MainActivity.kt:28`
如果同时发起多个权限请求，`permissionFuture` 会被覆盖。虽然当前场景不太可能发生，但属于潜在隐患。
