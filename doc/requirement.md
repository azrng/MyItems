## 1. 项目概述

### 1.1 定位

个人/家庭自用的 Android 物品管理 App「暖仓 WarmPantry」，slogan：**把日子过得清清楚楚** 🧺。核心功能是跟踪物品保质期与余量消耗，同时管理物品的分类、存放等信息。到期追踪与开封后有效期追踪是核心亮点功能，但不是唯一功能。

### 1.2 目标用户

个人/家庭自用，不上架应用商店。为爱囤货的家庭设计，四类物品全覆盖（食品、日用、美妆、药品）。

### 1.3 物品类型

覆盖所有类型：
- 食品/食材（有保质期，部分开封后有建议限期）
- 日用清洁（洗衣、厨卫清洁用品，多为耗品）
- 美妆护肤（开封后有效期 PAO 追踪）
- 药品保健（OTC、维生素、医疗器械）
- 耐用品（电器、数码周边等，无保质期，可通过「计为耗材」开关豁免消耗逻辑）

## 3. 数据模型

### 3.1 Item（物品）

| 字段 | 类型 | 说明 |
|------|------|------|
| Id | Guid | 主键 |
| Name | string | 物品名称 |
| Spec | string? | 规格（如 250ml×12、500g、20片） |
| CategoryId | Guid | 所属分类 |
| Barcode | string? | 条形码（可为空） |
| Icon | string? | 图标标识（emoji） |
| IsConsumable | bool | 是否计为耗材，默认 true；耐用品设为 false 后不参与余量消耗与用量提醒 |
| LastLocationId | Guid? | 最近一次批次的存放位置，再次录入时自动带出 |
| IsArchived | bool | 耗尽归档标记，用于隐藏已消耗完成的物品 |
| CreatedAt | DateTime | 创建时间 |
| UpdatedAt | DateTime | 更新时间 |

### 3.2 Batch（批次）

| 字段 | 类型 | 说明 |
|------|------|------|
| Id | Guid | 主键 |
| ItemId | Guid | 关联物品 |
| ExpiryDate | DateTime? | 保质期截止日（空 = 无保质期） |
| OpenedAt | DateTime? | 开封日期（空 = 未开封） |
| OpenShelfLifeDays | int? | 开封后建议使用天数（如面包 4 天、开封奶油 7 天、化妆品 PAO 折算天数） |
| LocationId | Guid? | 存放位置 |
| InitialQuantity | double | 初始数量，默认 1 |
| RemainingQuantity | double | 剩余数量，支持小数（如 −½ 盒、−8ml 估算），默认等于初始数量 |
| Unit | string | 计量单位（袋/盒/片/ml/包…） |
| Notes | string? | 备注（开封日期、口味等） |
| PurchasePrice | decimal? | 购入单价（选填，仅记录，不参与任何统计） |
| PurchaseDate | DateTime? | 购买日期（选填） |
| ImagePath | string? | 物品照片路径 |
| BatchLabel | string | 批次标签（自动生成，如时间戳） |
| CreatedAt | DateTime | 创建时间（入库时间） |

**有效到期日规则：** `EffectiveExpiryDate = min(ExpiryDate, OpenedAt + OpenShelfLifeDays)`（两者都存在时取较早者；仅有其一则取该值）。

### 3.5 InventoryLog（库存流水）

> 由原 ConsumptionRecord 扩展而来：同一份流水统一记录入库、消耗、归档三类事件，支撑消耗记录时间线中的"+入库"条目。

| 字段 | 类型 | 说明 |
|------|------|------|
| Id | Guid | 主键 |
| ItemId | Guid | 关联物品 |
| BatchId | Guid? | 关联批次 |
| Type | string | 类型：`intake` 入库 / `open` 开封 / `consume` 消耗 / `archive` 用完归档 / `adjust` 余量校正 |
| Quantity | double | 变动数量（正值，方向由 Type 决定） |
| Unit | string | 计量单位（冗余自批次，供流水独立展示） |
| LocationText | string? | 发生时的位置文本快照（如"来自 冰箱冷藏"） |
| Source | string | 来源：手动录入 / 快捷消耗 / 快捷再入库 / 再买一次 / 余量校正 |
| Note | string? | 补充说明（如"−8 ml（估算）"、校正前后数值、取消开封留痕） |
| CreatedAt | DateTime | 发生时间 |

**撤销语义：**「撤销最近一笔消耗」仅在确认后的短窗口内（约 5 秒 Snackbar，见 4.3/4.8）可用，实现为物理删除该笔流水并还原余量，不产生反向流水；窗口外的纠正一律走 `adjust` 余量校正留痕。

## 4. 业务规则

### 4.1 保质期状态与颜色分级

基于批次的 `EffectiveExpiryDate` 计算：

| 状态 | 条件 | 颜色/标签 |
|------|------|-----------|
| 已过期 | 有效到期日 < 今天 | 红色 |
| 紧急（≤24 小时） | 距到期不足 1 天 | 红色，临期页置顶，"DUE IN 1 天" |
| 预警 | 今天 ~ 今天+3 天 | 橙色；超过预警阈值（默认 3 天，可在设置调整）即触发本地通知 |
| 注意 | 今天+4 ~ 今天+7 天 | 黄色（卡片角标如"还剩 5 天"） |
| 安全 | 有效到期日 > 今天+7 天 | 绿色（角标"安全"） |
| 无期限 | 有效到期日为 null | 灰色 |

**临期专页筛选分组 chips：** 全部 / 24 小时内 / 3 天内 / 7 天内 / 已开封超限。
**物品库默认排序：** 按到期时间升序（最早到期在前），可切换添加时间倒序。

### 4.2 开封追踪规则

- 批次开封时记录 `OpenedAt`；若分类/物品有建议限期模板（如面包开封 4 天、蜂蜜开封按月、化妆品 PAO 按月折算为天数），填入 `OpenShelfLifeDays`。
- 开封后的有效期独立于原始保质期计算（见 3.2 有效到期日公式），超过开封限期的物品进入"已开封超限"分组参与临期预警。
- 界面展示形式：「开封第 2 天」「开封 150 天」「开封满 6 个月（PAO）」。
- 未开封数量型物品（如整箱牛奶 12 盒）按整体到期日展示「整箱至 08-30」。

**开封操作的用户路径：**
- 主入口：物品详情页（§5.13）批次卡上的「开封」按钮——填写开封日期（默认今天）与开封后建议限期天数（分类有模板则预填，如面包 4 天、防晒霜 PAO 折算 180 天），确认后写一条 `open` 流水；
- 快捷入口：物品库卡片长按菜单中的「开封」（默认今天 + 分类模板天数，可到详情页再改）。

**开封纠错路径（均在详情页批次卡内完成）：**
- 「取消开封」：清空 OpenedAt 与 OpenShelfLifeDays，并写入一条 Note 为「取消开封」的 `adjust` 流水留痕；
- 修改开封日期或限期天数：直接更新批次字段，并写入 `adjust` 流水在 Note 中记录旧值，保证 EffectiveExpiryDate 变化可追溯。

### 4.3 余量与消耗规则

- 消耗中心「正在消耗」展示所有 `IsConsumable=true` 且未归档的进行中批次，显示剩余百分比进度条。
- 「−1」快捷减量：默认减少 1 个计量单位，写入一条 `consume` 流水；支持小数减量（如 −½、−8 ml 估算）。
- 「✓ 用完」：弹出二次确认底部弹层（「这件物品将从库存移除并写入消耗记录」），确认后将余量扣为 0、写入 `archive` 流水并移入耗尽归档。
- 物品库卡片上的「−」＝对当前在库批次按有效到期日最早的批次做 −1 快捷消耗，无需进入详情页；多批次并存时按有效到期日升序跨批次 FIFO 扣减，前一批扣尽自动落到下一批。
- 物品库卡片上的「＋」＝快捷再入库：弹出轻量面板预填上次规格（名称/规格/单位/位置），确认后**新建一个批次**（效期默认沿用上次值、可修改），与 4.6「每购一批存一批」及 4.4「再买一次」口径一致，写入 Source=快捷再入库 流水。
- 余量 ≤ 25%（可配置）时卡片显示低余量标签（如「剩 25%」「余量低」）。
- 耗尽归档后物品不出现在首页、物品库有效列表与临期页。
- 耐用品（IsConsumable=false，如数码周边）不进入"正在消耗"列表，不做用量提醒。

**消耗落点规则：** 所有消耗动作（正在消耗行、卡片步进器、记录消耗弹层）统一按 有效到期日升序 的在库批次依次扣减；扣减对象始终是批次而非物品。

**余量校正：** 正在消耗行与详情页批次卡提供「校正」入口，可将当前余量改为任意值（含清零）；每次校正写入一条 `adjust` 流水（Note 记录调整前后数值与原因），用于修正漏记、误记导致的账实不符。

**撤销最近一笔消耗：** 任一入口确认后弹出的 Snackbar 提供 5 秒「撤销」，撤销为物理删除该笔流水并还原对应批次余量（见 3.5 撤销语义）；离开窗口后只能通过余量校正纠正。

### 4.4 回购规则

- 耗尽归档列表提供「再买一次」按钮：按上次规格预填添加页完成快速录入，同时生成一条回购清单记录（toast：「已按上次规格生成采购单 🛒」）。
- 归档条目可标记「好用想回购 ⭐」，回购清单状态在「待购 → 已在购物车」间流转。
- 归档统计：累计用完数、平均使用周期（归档时间 − 入库时间均值）、本月归档数。

### 4.5 存放位置与容量规则

- 位置按所属区域分组展示（🏠 厨房区域 / 🚿 卫生间区域 / 🛋 居住区域 / 自定义区域），新建位置时选择预设区域或输入新区域名。
- 位置可设置容量上限（默认建议 10 件）；当前在库件数达到上限时提示「放满会提醒你『别再囤啦』」（软提醒，不阻断录入）。
- 每个位置卡片展示：在库件数、临期件数（如「2 件临期」）、容量占用进度条。
- 效期敏感区域（如家庭药箱）可展示「效期强提醒区域 ⚠️」角标文案。

### 4.6 录入流程

1. 点击 FAB「＋」或快捷入口「添加物品」进入添加页，依次填写：物品名称*、规格（选填包装描述，如 250ml×12 / 500g / 20片）、分类*（8 类宫格单选）、存放位置*（宫格单选，末位「➕ 新增位置」可就地建位）、数量步进器 + 计量单位（常用单位 chips + 自定义输入，默认带出上次使用的单位）+ 「计为耗材」开关、到期日期（提供常见保质期快捷选项与自定义）、单价与购买日期（选填，默认留空）、提醒设置开关（默认开）、备注。
2. 存放位置默认带出 `LastLocationId`（上次使用的位置）。
3. 「存草稿」保存表单快照，下次进入可恢复；每个购买批次作为一条新的批次记录保存，不自动合并到已有物品（同一物品多批次并存于其详情中）。
4. 保存时执行**同名检查**：检测到同名物品时提示用户，可选择挂到已有物品下作为新批次，或确认为新物品。
5. 「保存并继续录入下一件」：手动连续录入模式，保存当前后表单重置返回录入态（扫码连续录入暂缓，见 2.2）。

### 4.7 编辑与删除流程

- 分类管理：点击分类行进入编辑弹层（预填名称/图标/颜色），可改名改色；预置分类不可删除，自定义分类删除前校验关联物品（见 4.8）。
- 存放位置：点击位置卡片进入编辑弹层（预填名称/图标/容量/区域），支持改换区域并自动迁移分组；删除即停用（IsActive=false），不影响历史记录。
- 物品：物品库点卡片复用录入页进入编辑（预填名称/数量/到期日等），保存更新；删除走二次确认物理删除（含批次与流水）。
- 原型以「点击进入编辑」演示；正式版按 4.8 补充左滑删除与长按多选批量操作。

### 4.8 删除与保护规则

- 物品删除 → 最终为物理删除（含批次与流水），但经「软删缓冲」两段式执行：确认后立即移出列表并进入待删集合，底部 Snackbar 提供 5 秒「撤销」，超时未撤销（或离开页面 / App 退出）才真正落盘清除；App 冷启动时清扫残留待删数据。左滑删除与长按多选批量操作（批量删除/批量移动位置/批量改分类）同样适用该撤销窗口；批量移动位置、批量改分类本身可逆，不设撤销。
- 预置分类不可删除；自定义分类删除前检查是否有关联物品。
- 存储位置删除为停用该位置（IsActive=false），不影响已有物品历史位置文本。
- 耗尽归档支持「清空」，清空前必须二次确认（仅清除归档记录，不动流水历史）。

### 4.9 本地通知细则

- 触发模式：每日一次聚合摘要通知（默认 08:30，时间可在设置调整），汇总当天临期/已过期数量与最紧急的 2–3 件，不做逐件连环轰炸；24 小时内到期项在摘要标题强化（如「⚠️ 2 件今天就到期」）。

**实现口径（关键：摘要 = App 内预计算 + 系统 AlarmManager 定时投递，进程死亡也能弹出）：**
- 库存数据只会在 App 内发生变化，因此摘要内容可以在调度时精确预计算：每次启动、每次数据变更、修改摘要时间后，按「下一个摘要时间点」重新计算内容（哪些批次在那个日期属于临期/已过期，由 EffectiveExpiryDate 确定性可得）并注册给系统闹钟，之后完全由操作系统投递。
- App 被关闭/进程被杀后通知照常弹出，不存在「关软件后无法聚合」；代价是文本来自最后一次 App 会话——由于数据无法在 App 外变化，预计算内容不会过时。
- Android 12+ 精确闹钟需 SCHEDULE_EXACT_ALARM 用户授权；未授权时降级为非精确闹钟，摘要最多延迟约 15 分钟（对每日摘要可接受）。
- 自愈机制：每次启动都取消并重挂闹钟（覆盖被系统取消的场景）；设备重启后由 flutter_local_notifications 的 BOOT_COMPLETED 接收器补挂；用户在最近任务中强停（force stop）会取消闹钟，属系统行为，靠下次启动自愈 + 保活指引缓解。
- 权限申请时机：Android 13+ 在用户主动点击首页铃铛或在「我的 → 提醒设置」打开开关时请求 POST_NOTIFICATIONS 运行时权限；拒绝后降级为站内铃铛红点 + 临期计数，不反复弹窗。
- 已过期物品不单独提醒，只在每日摘要中出现，避免红标焦虑。
- 点击通知跳转临期预警专页。
- 错过当日窗口（如闹钟被杀、手机关机）：不做系统通知补弹——用户打开 App 时站内铃铛红点与首页统计卡本就实时承载同样信息，弹窗反而打扰；当日闹钟随本次启动自动重挂。
- 国产 ROM 后台查杀可能导致提醒延迟或不准：「关于我们」页保留保活设置指引占位文案。
- 物品级提醒开关作用粒度：作用于物品，聚合其全部在库批次的最早有效到期日判断是否提醒。

### 4.10 图片生命周期

- 采集：拍照/选图后压缩保存——长边 ≤1280px、JPEG 质量 ≈80，原图不入库；本期不做独立缩略图文件，列表直接使用压缩图。
- 更换照片：先覆盖旧图片文件再更新 ImagePath，不留双份。
- 清理：删除物品（连带批次）与归档清空时，对应图片进入待清理集合，由**完整备份成功之后**运行的孤儿扫描统一删除（先备份后清理，顺序不可反）；应用冷启动对待清理集合做一次兜底清扫。仍被任一记录引用的图片一律跳过。
- 图片目录与数据库目录分离，§5.11 存储占用概览分别统计。

### 4.11 统计口径

| 指标 | 定义 |
|------|------|
| 今日消耗 | 当天 `consume` 类型流水的笔数（不合并同物品多笔） |
| 本周消耗节奏 | 近 7 天每日 `consume` 流水件数柱状图 |
| 连续记录天数 | 以本地日历日为单位：当天存在任意一条库存流水即记为活跃；从最后一个活跃日起向回连续计数，中断即清零；耐用品无流水不豁免（无记录就是未记录） |
| 节流成就 | max(0, 上月消耗件数 − 本月消耗件数)，展示为「比上月少用 N 件」；公式为 P2 初版，后续可演进 |
| 平均使用周期 | 归档物品（归档时间 − 入库时间）均值，见 4.4 |

- **批次卡（核心单元）**：批次标签、余量进度条与百分比、到期日与 4.1 状态色角标、开封态文案（未开封 / 开封第 N 天 / 开封满 X 月 PAO）、存放位置；卡内操作：

- **空状态**：防御性兜底——无任何在库批次时显示空态插画 + 「＋ 再次入库」按钮。

## 7. 备份与导出格式

Android 版本提供完整备份导出（ZIP），并支持通过系统分享面板发送给其他设备。

### 7.1 完整备份（推荐用于换手机）

- 文件名：`warmpantry_backup_时间.myitems.zip`
- 包结构（ZIP）：
  - `backup.json`：全部数据；格式标识 `azrng.warm_pantry.backup`，schema 版本 `4`（Item/Batch 拆分与流水重构；导入端须兼容读取 v3 及更早的纯 JSON 格式并映射升级）
  - `images/`：物品照片文件，按批次 ImagePath 文件名原样打包（不重命名、不转码；照片入库时已按 4.10 压缩，此处直接复用）
- 采用 ZIP 而非 base64 内嵌的原因：体积约省 25%、序列化与恢复更快、照片文件可原样回填；恢复端以 ZIP 条目 CRC + `backup.json` schema 校验为「校验通过 ✓」依据
- 导出位置：写入手机公共「下载 / Download/WarmPantry」目录，便于文件管理器查找和拷贝
- 权限说明：Android 9 及以下设备导出到公共下载目录时，需要在用户触发导出后申请写入存储权限
- `backup.json` 内容范围：
  - `categories`：全部分类（含颜色、排序、预置/自定义与停用状态）
  - `locations`：全部存储位置（含区域、图标、容量、停用状态）
  - `items`：全部物品（含规格、耗材标记、归档物品）
  - `batches`：全部批次（含开封追踪字段与 ImagePath 对应文件名）
  - `inventoryLogs`：全部库存流水（入库/开封/消耗/归档/校正）
  - `repurchases`：回购清单
  - `settings`：应用设置（主题模式、预警天数等）
  - `exportedAt`：导出时间

**自动备份规则（P1，本机通道）：**
- 每日在设定时间将数据库连同图片导出一份完整备份到应用私有目录/公共下载目录
- 保留最近 N 份（默认 5），超出滚动淘汰最旧备份
- 备份完成后更新「上次成功备份时间 + 大小 + 校验状态」并展示在存储与备份页
- **失败态处理**：备份失败（磁盘满、目录不可写等）当日内静默不再重试，次日窗口重试；App 回到前台且距上次成功超过一天时立即补试一次。失败状态以红色 pill 展示在存储与备份页与「我的」对应菜单行，附原因摘要；提供「立即备份」手动触发按钮，不等每日窗口
- 校验对应展示：显示「校验通过 ✓」的前提是校验成功；校验失败展示「校验未通过」并引导「重新导出」，不得静默标记成功

**导入/恢复规则：**
- 用户通过系统文件选择器选择 `.myitems.zip` 备份包；旧版纯 `.myitems.json` / `.json` 备份仍可导入（映射升级到当前 schema）
- 导入前二次确认，导入后用备份内容覆盖当前手机数据；图片文件恢复后需与批次 ImagePath 逐一核对，缺失图片的批次按无照片处理，不阻断导入
- **恢复后悔药**：覆盖前自动把当前完整数据导出一份 `warmpantry_pre_restore_时间.myitems.zip`（同 7.1 结构）至同目录，恢复失败或误恢复时可退回
- 导入完成后重新补齐预置分类和预置存储位置（见 §3.9 / §3.10），避免旧备份缺少新版预置数据
- 若备份中的流水关联物品已被删除，记录页显示「已删除物品」

## 8. 非功能需求

| 项目 | 要求 |
|------|------|
| 启动速度 | 冷启动 < 2 秒 |
| 数据量 | 支持至少 1000 条批次记录无卡顿 |
| 数据安全 | 本地存储，无网络传输 |
| 存量数据迁移 | 旧版扁平 Item 结构（sqflite）升级为 Item/Batch 与新流水结构时必须提供迁移脚本，逐字段映射进新表并在迁移后校验总数一致；禁止删库重建；迁移前引导用户先手动导出一份完整备份 |
| 通知 | 仅系统本地通知，无推送服务器依赖 |
| 备份 | 支持手动导出完整 ZIP 备份（数据 + 图片）到本地文件系统，支持每日本机自动备份，并可导入到另一台手机 |
