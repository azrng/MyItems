# 我的物品 — 物品管理 App 设计文档

> 创建日期：2026-05-02
> 状态：已确认，待实施

---

## 1. 项目概述

### 1.1 定位

个人/家庭自用的 Android 物品管理 App，核心功能是跟踪物品的保质期，同时管理物品的购入、存放等信息。到期追踪是核心亮点功能，但不是唯一功能。

### 1.2 目标用户

个人/家庭自用，不上架应用商店。

### 1.3 物品类型

覆盖所有类型：
- 食品/饮料（有保质期）
- 化妆品/护肤品（有保质期）
- 药品/保健品（有保质期）
- 日用品（电池、清洁剂等，部分有保质期）
- 耐用品（显示器、电器等，无保质期）

## 2. 功能需求

### 2.1 核心功能

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 物品录入（手动） | 表单填写物品名称、分类、单价、存放位置、购买日期、保质期、初始数量等 | P0 |
| 物品录入（扫码） | 扫条形码自动填充，Flutter 版本暂时隐藏入口 | P1 |
| 主页列表 | 按添加时间倒序展示全部有效物品 | P0 |
| 临期提醒 | 独立页面按过期/临期分组展示，到期追踪为核心功能 | P0 |
| 物品库 | 展示所有有效物品，支持分类筛选、搜索、详情查看和左滑删除 | P0 |
| 分类管理 | 预置分类 + 自定义分类 CRUD | P0 |
| 数据导出/导入 | 完整 JSON 备份用于跨手机迁移，CSV 作为表格兼容工具 | P1 |
| 搜索 | 首页、临期页、物品库使用独立搜索状态 | P1 |
| 存放位置管理 | 侧边栏进入存储位置页面，维护添加物品时的下拉选项 | P1 |
| 物品消耗 | 支持用掉一件、消耗完成、消耗记录和耗尽归档 | P0 |
| 统计概览 | 按有效物品剩余数量统计有效花费、有效商品数、全部商品数 | P2 |

### 2.2 不在范围内（MVP）

- 推送通知（仅打开时查看）
- 云端同步
- 多用户/账号系统
- OCR 识别
- 上架应用商店相关（多语言、隐私合规等）

## 4. 业务规则

### 4.1 状态判断

基于 Batch 的 ExpiryDate 计算保质期状态：

| 状态 | 条件 | 颜色 |
|------|------|------|
| 已过期 | ExpiryDate < 今天 | 红色 |
| 临期 | 今天 <= ExpiryDate <= 今天+7天 | 黄色 |
| 安全 | ExpiryDate > 今天+7天 | 绿色 |
| 无保质期 | ExpiryDate 为 null | 蓝色 |

**主页排序规则：** 按创建时间倒序展示有效物品。

**临期页排序规则：** 仅展示已过期和临期物品，按保质期日期升序展示。

### 4.2 录入流程

1. 用户点击"添加"，填写物品信息、单价、购买日期、存放位置、保质期和初始数量。
2. 每次购买都作为一条新的物品记录保存，不自动合并到已有物品。
3. 保存后首页和物品库按创建时间倒序刷新。

### 4.3 扫码流程

1. 点击扫码按钮 → 打开摄像头 → 扫到条形码
2. 调用 Open Food Facts API 查询商品信息
3. 本地已有该条形码的物品 → 自动关联，用户只需填写批次信息
4. 新商品 → 自动填充名称，用户补充分类、过期日期等

### 4.4 消耗规则

- 「用掉一件」：剩余数量减 1，并写入一条消耗记录。
- 「消耗完成」：将剩余数量一次性扣为 0，并写入消耗记录。
- 剩余数量为 0 后，物品进入耗尽归档，不再出现在首页、临期页和物品库有效列表中。
- 侧边栏提供「耗尽归档」和「消耗记录」入口；消耗记录展示物品名称、消耗类型、数量和日期。
- 有效花费 = 单价 × 剩余数量；未记录单价时按 0 计。

### 4.5 删除规则

- 物品删除 → 物理删除，删除前必须给足确认提示
- 预置分类不可删除，自定义分类可删除（需确认该分类下无物品）
- 存储位置删除为停用该位置，不影响已有物品历史位置文本

## 7. 数据导出格式

Flutter Android 版本提供两类导出：

### 7.1 完整备份（推荐用于换手机）

- 文件名：`my_items_backup_时间.myitems.json`
- 格式标识：`azrng.my_items.backup`
- schema 版本：`2`
- 导出位置：通过系统保存文件流程写入用户可见位置，通常选择或保存到手机「下载 / Download」目录。
- 内容范围：
  - `categories`：全部分类，包含预置、自定义和停用状态
  - `locations`：全部存储位置，包含停用状态
  - `items`：全部物品，包含有效物品和耗尽归档物品
  - `consumptionRecords`：全部消耗记录
  - `settings`：应用设置，例如主题模式
  - `exportedAt`：导出时间

**导入规则：**
- 用户通过系统文件选择器选择 `.myitems.json` / `.json` 备份文件。
- 导入前二次确认，导入后用备份内容覆盖当前手机数据。
- 导入完成后重新补齐预置分类和预置存储位置，避免旧备份缺少新版预置数据。
- 若备份中的消耗记录关联物品仍存在，消耗记录页面显示物品名称；物品已被删除时显示「已删除物品」。

### 7.2 CSV 兼容工具

- CSV 仅用于人工查看或兼容旧数据导入。
- CSV 不作为完整迁移备份，不包含消耗记录、设置等完整上下文。
- CSV 导入继续兼容旧字段 `price`、`quantity`，并映射到当前的单价、初始数量和剩余数量。

## 8. 非功能需求

| 项目 | 要求 |
|------|------|
| 启动速度 | 冷启动 < 2 秒 |
| 数据量 | 支持至少 1000 条批次记录无卡顿 |
| 数据安全 | 本地存储，无网络传输（除扫码查询 API） |
| 备份 | 支持手动导出完整 JSON 备份到本地文件系统，并导入到另一台手机 |
